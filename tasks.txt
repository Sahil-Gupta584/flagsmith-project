PHASE 2: DECLARATIVE YAML SCHEMA SPECIFICATION
================================================================================
[x] YAML Schema Design (`flags.yaml`)
    - Project headers (version: 1, project.id, project.name).
    - Standard Boolean Flags:
      * key, description, default_enabled state.
    - Multivariate Flags & Experiment Metrics:
      * string, integer, boolean values with percentage allocations summing to 100%.
      * Native `target_metric` specification (name, description, aggregation, direction)
        matching Flagsmith's Experimentation API.
    - Multi-Environment Overrides:
      * Environment-specific state (`development`, `staging`, `production`).
    - Metadata flags:
      * `archived` state.

[x] Schema Validator & Linter (`fm validate`)
    - Offline linting against Zod schema.
    - Checks for duplicate flag keys, invalid percentage rollouts (sum != 100%),
      and missing required fields before hitting the API.

PHASE 3: CORE COMMANDS (PRISMA/DRIZZLE MODEL)
================================================================================
[x] Command: `fm init`
    - Interactive CLI setup wizard using @clack/prompts:
      * Authenticates with Flagsmith.
      * Prompts to select Project & Environments.
      * Generates initial boilerplate `flags.yaml` or triggers initial `fm pull`.
      * Offers to save credentials to local .env.

[x] Command: `fm pull` (Introspect / Reverse-Sync)
    - Equivalent to `prisma db pull`.
    - Fetches the current live state of all features and environments from Flagsmith API.
    - Serializes live state cleanly into formatted `flagsmith.yaml`.

[x] Command: `fm diff` (or `fm status`)
    - Equivalent to `prisma migrate diff` / `git diff`.
    - Performs direct 2-way comparison: Local `flagsmith.yaml` vs Live Flagsmith API.
    - Terminal UI with syntax highlighting:
      * [+] Green: Flags/overrides to create.
      * [~] Yellow: Flags/rules with modified values or toggles.
      * [?] Dim: Untracked remote flags.
      * [-] Red: Flags marked for removal/pruning.

[x] Command: `fm apply` (or `fm push`)
    - Equivalent to `prisma db push` / `kubectl apply`.
    - Reconciles desired state from `flagsmith.yaml` to Flagsmith Management API.
    - Dry-run mode (`--dry-run`) to preview mutations without applying.
    - Auto-confirm mode (`-y` / `--yes` / `--force`) for non-interactive execution.
    - Safe pruning strategy: non-destructive by default; absent flags in YAML are preserved unless `--prune` is passed.
